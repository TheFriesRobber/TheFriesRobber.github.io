Agent 05：长对话压缩必须保留可重建的来源边界

用 coverage、dependency closure、revision 和安全 recent window，让长对话摘要可以失效、重建并响应更正。

Agent CoreAgentContext EngineeringCompression

问题

一个 Agent 已经讨论了七十轮市场报告。较早对话被压缩成摘要：“报告覆盖欧洲与北美。”随后用户明确更正：“只保留欧洲。”Context Assembly 为了控制 token，仍把旧摘要和最新二十条消息交给模型。

如果只靠模型同时阅读二者，它可能继续生成北美部分；如果原地把摘要改成“仅欧洲”，系统又失去了旧摘要覆盖哪些原文、为什么改变，以及删除或权限撤销后还应重建哪些派生内容。

对话压缩不是把旧消息写短。它是在保留 raw history 的前提下生成一个带覆盖范围、来源依赖和 revision 的 Context projection；只有这样，更正、删除和授权变化才有明确的失效与重建路径。

Raw history 与 Summary 拥有不同责任

Raw history 保存已经提交的用户消息、模型回复、Tool Call 和 Tool Result。Summary 是为预算服务的派生视图，不应成为新的事实源。

一次投影可以分成三个区间：

stable raw prefix → checkpoint summary
recent stable units → raw recent window
in-flight work → not compressible

只有已经达到稳定边界的前缀可以压缩。正在生成的模型输出、尚未收敛的 Tool batch 和等待确认的动作仍可能变化，不能因为接近窗口上限就写进摘要。

这也解释了为什么“保留最近 N 条消息”不是完整 contract：消息数没有表达 Tool Call/Result 配对、纠错关系或未完成工作。

Pi 当前只提供 Context 投影插口

Pi 当前的低层 Loop 允许宿主为每轮提供 transformContext(messages, signal)，在模型调用前变换消息；它不拥有本文所说的 Summary metadata、active revision CAS、授权依赖失效或 rebuild controller。这个 callback 的契约还要求转换失败时返回 safe fallback，而不是向 Loop 抛错。

因此，needs_rebuild 不能靠 transformContext 临场 throw 来阻止模型消费旧 Summary。拥有持久化 Summary 的宿主必须在进入低层 Loop 前完成 revision/authorization 检查：合法视图准备好才调用 Loop；否则等待重建、使用不含失效 Summary 的安全投影，或显式终止本轮。Pi 的当前插口可参考固定版本的 agent-loop.ts；本文其余 CAS 与重建协议属于宿主层。

Coverage 说明摘要代表哪一段历史

每份 summary 至少要声明覆盖范围和 active revision：

summary_id: summary_4
revision: 4
covers:
  stream_ref: session:17
  from_seq: 1
  through_seq: 420
replaces: summary_3
policy_revision: compression-v2

covers 只回答“这份摘要代表哪段 event interval”。它让 Assembly 检查 summary 与 recent window 是否重叠或出现缺口，却不能证明摘要内容的来源仍然有效。

新 summary 通过 compare-and-swap（CAS）切换为 active：提交时同时检查旧 active revision、event watermark 和 compression policy revision。若后台压缩期间又有新更正到达，CAS 失败，旧结果不能覆盖更新后的视图。

Dependency closure 决定什么变化会使摘要失效

Summary 还要记录完整来源依赖：

dependencies:
  source_spans:
    - event_seq: 1..420
  content_refs:
    - message:msg_18
    - tool_result:result_31
  previous_summary_backlinks:
    - summary_3
  decision_refs:
    - assembly_decision:decision_27
authorization_revision: authz_19
retention_revision: retention_6

Coverage interval 与 dependency closure 不是一回事。一个后续 Tool Result 可能复述已删除文件的内容；一个 summary 也可能复用上一版 summary。只按 event interval 查找直接来源，会漏掉这些传递依赖。

当来源被删除、权限撤销或 retention policy 改变时，系统沿 dependency closure 标记所有直接和间接派生 summary 为不可用。它不能因为摘要文本仍存在，就继续把已经失效的来源暴露给模型。

增量推进必须保留 Rebuild 路径

平时可以用 previous summary + 新稳定前缀 生成下一版，避免每次重新读取全部历史。但无限总结上一版会累积遗漏和语义漂移。

以下变化应触发从仍可读取的 raw history 重建，而不是继续叠加：

  • 用户更正了摘要中的目标、事实或约束；
  • compression policy、模型或结构发生不兼容变化；
  • Eval 发现连续压缩会稳定丢失某类信息；
  • 任一来源、授权或 retention dependency 已失效。

如果仍能读取合法来源，就只重建受影响范围；如果无法确认剩余内容独立于失效来源，summary 进入 needs_rebuild 并退出 Context。显式失败比继续使用无法证明来源的摘要更安全。

更正先进入历史，再推动新 Revision

回到“只保留欧洲”。用户更正先成为新的 raw event，系统不直接覆盖 summary_3：

summary_3 covers seq 1..420: 欧洲与北美
seq 421: 用户更正为只保留欧洲

Assembly 先判断更正的适用范围。如果它只影响当前回答，可以保留在本轮 Context view；如果它改变后续对话的长期目标，compression owner 使用合法来源重建覆盖区间，生成 summary_4：

summary_4 covers seq 1..420
replaces summary_3
decision_ref: correction at seq 421
current goal: 仅完成欧洲市场报告

更正事件本身仍留在 recent window 中。summary_4 校验通过并原子切换 active 后，后续 Turn 才消费它。这样系统既保留“为什么改”，也不会让新更正与旧摘要同时竞争。

Recent Window 必须从安全边界开始

Recent window 应从目标 token 大小向前寻找完整语义单元，而不是机械保留固定条数。左边界至少不能：

  • 切开 Tool Call 与对应 Tool Result；
  • 切开用户更正与它否定的当前约束；
  • 越过尚未完成的确认、Plan item 或执行阶段；
  • 只保留“已完成”的模型陈述，却删除随后指出失败的证据。

如果找不到满足预算的安全边界，Assembly 应压缩更早的完整单元、换用更大窗口或明确失败。尾部截断不能以破坏执行因果为代价。

压缩验收不能只看 Token 下降

可信 Summary 至少需要验证：

  • 任务目标、用户约束和关键事实是否保留；
  • 结论能否追溯到仍有效的 source reference；
  • 新更正是否覆盖旧约束，而不是与旧 Summary 并存；
  • Tool Call 与 Tool Result 是否保持配对和因果顺序；
  • 多轮增量压缩后，遗漏与语义漂移是否超过门限。

这些维度分别进入后续的 Context Assembly Evaluation 与生产 Eval 闭环。Token reduction 只是成本结果；如果约束保留、来源或纠错失败，压缩不能因为更短而通过。

回到问题

旧摘要说“欧洲与北美”，新消息说“只保留欧洲”时，正确做法不是让模型猜哪句更可信，也不是静默覆盖一段文本：

  1. raw history 保留旧事实和新更正；
  2. summary 用 coverage 说明自己代表的稳定区间；
  3. dependency closure 连接来源、先前摘要和 Assembly Decision；
  4. 更正、删除、授权或 policy 变化使旧 revision 失效；
  5. compression owner 从仍合法的来源重建并以 CAS 切换 active summary；
  6. recent window 从不切断 Tool、纠错或未完成执行的安全边界开始。

压缩节省的是模型输入，不是事实责任。Summary 可以被替换、失效和重建，raw history 才能继续回答“这段 Context 从哪里来，为什么现在是这一版”。
