Context Assembly Evaluation Cannot Stop at Recall

Evaluate a Context projection with required information, citations, pollution, conflict handling, and budget efficiency.

07/24/2026 Views
Agent VerificationAgentEvaluationContext Engineering

The problem

A user corrects an instruction: “Send future weekly reports to the project channel, not by direct message.” Retrieval finds the message, so recall is perfect. Old Memory still says “send by direct message,” however, and appears after the correction. Under budget pressure, compression removes the correction.

The model chooses a direct message. Retrieval found the relevant content, but the final Context is wrong.

Retrieval produces candidates. The model input also passes through selection, conflict handling, ordering, compression, permission, and provider shaping. Context Eval should test the resulting projection with provenance, not merely what vector search returned.

Checking only the response blames Context for model behavior; checking only candidates misses later failures. Every case declares the layer it evaluates.

Cases define Required, Distractor, Conflict, and Unsafe inputs

required:
  - id: user_correction_v2
    fact: delivery_channel = project_channel
    source: current_user_message
distractor:
  - id: unrelated_meeting_note
conflicting:
  - id: preference_v1
    fact: delivery_channel = direct_message
    source: memory
    superseded_by: user_correction_v2
unsafe:
  - id: other_tenant_preference

These are grader labels, not model-visible answers. They test whether required information survives, distractors waste budget, conflicts are handled, and unsafe items are rejected. An item may play a different role in another case; classification depends on objective, time, and policy.

Measure coverage in the final projection

retrieval recall
= recalled required items / all required items
Context coverage
= required facts still usable in provider-shaped Context
/ all required facts

“Usable” is semantic. Compression that changes “do not send a direct message” into “discuss report delivery” loses the negation. Content hidden in metadata the model cannot see does not count.

Coverage grading may combine deterministic identity/provenance checks, rules for structured constraints, and a calibrated semantic grader for summary equivalence.

Provenance and citations test where a fact came from

A correct answer may come from parametric memory or a stale source. Preserve source identity, revision, time, permission domain, and transformation lineage:

context_item_9
  ← user_message_22
  ← transformed_by compression@5
  ← included_by assembly_policy@8

When output citations are required:

citation coverage
= claims with required citations / claims requiring citations

citation correctness
= citations that support their claims / all actual citations

Claim and citation denominators answer different questions. A cited claim can pass coverage and fail correctness.

Pollution measures harmful inclusion, not only omission

missing: required item absent
pollution: irrelevant or harmful item included
override: weaker or stale fact defeats authoritative fact

Pollution may be measured by item:

included distractor items / all included items

or by tokens, using an actual tokenizer or stated estimate. One long distractor may be one item but consume most of the budget.

Unauthorized content is a separate hard failure, not a small pollution percentage:

projections containing at least one unauthorized item
/ all evaluated projections

Permission must hold before model exposure, regardless of whether the answer repeats the secret.

Conflict handling needs explicit precedence

current explicit user correction
  supersedes
older preference Memory for the same subject

The grader checks conflict detection, inclusion of the authoritative item, removal or marking of the stale item, absence of unresolved dual instructions, and whether degradation protected the wrong value.

When policy cannot determine authority, preserving the conflict and asking for clarification may be correct. unknown is valid.

Budget efficiency must be defined with value

Shorter is not automatically better. Useful diagnostics include:

required facts preserved / final Context tokens
distractor tokens / final Context tokens
final Context tokens / configured Context budget

Compare efficiency only after configurations preserve required facts, permissions, and conflict rules on the same cases and model configuration. State the tokenizer or counting method; no universal optimum exists.

The degradation order is also testable:

protect first: current constraints, unresolved Tool Results, authoritative corrections
compress next: history superseded by later messages
drop last: irrelevant candidates

Deleting the current correction first violates the contract even if the result fits the token budget.

Each case stores source fixtures, assembly configuration, provider-shaped Context fingerprint, and grader version so a change can be localized to retrieval, assembly, or adapter.

Perfect recall can still produce a failed Context

retrieval:
  required_items_found: 1/1
projection:
  required_facts_preserved: 0/1
  stale_conflicts_included: 1
  authoritative_conflict_winner: fail
  unauthorized_items: 0
budget:
  within_limit: true
  degradation_order: fail
context_outcome: fail

Recall is 1/1, but the required fact disappeared and stale Memory won. The Context may contribute to the model’s direct-message choice, yet response failure still needs separate evaluation rather than being assigned to assembly from correlation alone.

Back to the problem

Finding all relevant candidates proves only that retrieval did not miss the required item. It does not prove that the model received a correct Context.

Context Eval fixes observable objects across source, retrieval, assembly, projection, and provider shaping, then tests required coverage, provenance, citations, pollution, conflict, permission, and budget degradation. Missing, wrongful inclusion, and wrongful override are distinct failures.

The opening high-recall case fails because the evaluation target must be what this Turn actually gave the model under its source, permission, conflict, and budget decisions—not merely what search found.
