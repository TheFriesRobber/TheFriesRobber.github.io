Agent 05: Long-Conversation Compression Must Preserve Rebuildable Source Boundaries

Use coverage, dependency closure, revisions, and a safe recent window so conversation summaries can be invalidated and rebuilt after corrections.

07/27/2026 Updated 07/27/2026 Views
Agent CoreAgentContext EngineeringCompression

The problem

An Agent has spent seventy turns discussing a market report. Earlier conversation has been compressed into the summary, “The report covers Europe and North America.” The user then corrects the scope explicitly: “Keep only Europe.” To control token use, Context Assembly still sends the old summary together with the most recent twenty messages.

If the model must resolve the contradiction on its own, it may continue producing the North America section. If the system overwrites the summary in place, it loses which source interval the summary covered, why it changed, and which derived content must be rebuilt after deletion or authorization revocation.

Conversation compression is not merely shorter old messages. It is a Context projection with coverage, source dependencies, and a revision, built while raw history remains authoritative. Those properties give corrections, deletion, and authorization changes an explicit invalidation and rebuild path.

Raw history and Summary have different responsibilities

Raw history preserves committed user messages, model responses, Tool Calls, and Tool Results. A Summary is a budget-oriented derived view, not a new fact source.

A projection can divide history into three regions:

stable raw prefix → checkpoint summary
recent stable units → raw recent window
in-flight work → not compressible

Only a prefix that has reached a stable boundary may be compressed. A model response still being generated, an unsettled Tool batch, or an action waiting for confirmation may still change. Approaching a context limit does not make those units safe to summarize.

This is also why “keep the latest N messages” is not a complete contract. Message count does not express Tool Call/Result pairing, correction relationships, or unfinished work.

Pi currently provides only a Context-projection slot

Pi’s low-level Loop currently lets the host supply transformContext(messages, signal) to transform messages before each model call. It does not own the Summary metadata, active-revision CAS, authorization-dependency invalidation, or rebuild controller described here. The callback contract also requires a safe fallback when transformation fails rather than throwing into the Loop.

needs_rebuild therefore cannot rely on transformContext throwing at the last moment to keep a stale Summary away from the model. The host that owns persisted Summaries must validate revision and authorization before entering the low-level Loop. It calls the Loop only with a legal view; otherwise it waits for rebuild, uses a safe projection without the invalid Summary, or terminates the Turn explicitly. See the pinned agent-loop.ts. The CAS and rebuild protocols in the rest of this article belong to the host layer.

Coverage states which history a Summary represents

Every Summary needs a coverage interval and active revision:

summary_id: summary_4
revision: 4
covers:
  stream_ref: session:17
  from_seq: 1
  through_seq: 420
replaces: summary_3
policy_revision: compression-v2

covers answers only which event interval the Summary represents. It lets Assembly detect overlap or gaps between the Summary and the recent window. It does not prove that every source used by the Summary remains valid.

The compression owner promotes a new active Summary with compare-and-swap (CAS), checking the previous active revision, event watermark, and compression-policy revision. If another correction arrives while background compression is running, CAS fails and the stale result cannot overwrite the updated view.

Dependency closure determines what invalidates a Summary

A Summary must also retain its complete source dependencies:

dependencies:
  source_spans:
    - event_seq: 1..420
  content_refs:
    - message:msg_18
    - tool_result:result_31
  previous_summary_backlinks:
    - summary_3
  decision_refs:
    - assembly_decision:decision_27
authorization_revision: authz_19
retention_revision: retention_6

A coverage interval and dependency closure are different. A later Tool Result may repeat content from a file that has since been deleted. A Summary may also reuse a previous Summary. Looking only for sources directly inside an interval misses these transitive dependencies.

When a source is deleted, authorization is revoked, or retention policy changes, the system follows dependency closure and marks every directly or indirectly derived Summary unavailable. Persisted summary text is not permission to keep exposing an invalid source to the model.

Incremental progress still needs a rebuild path

The normal path can generate a new revision from previous Summary + new stable prefix, avoiding a full-history read every time. Indefinitely summarizing the previous Summary, however, accumulates omissions and semantic drift.

The following changes should rebuild from still-readable raw history rather than continue the chain:

  • the user corrects a goal, fact, or constraint represented by the Summary;
  • the compression policy, model, or structure changes incompatibly;
  • Evaluation finds a class of information that repeated compression consistently loses;
  • a source, authorization, or retention dependency becomes invalid.

When legal sources remain available, the owner rebuilds only the affected range. When it cannot establish that retained content is independent of an invalid source, the Summary becomes needs_rebuild and leaves Context. Explicit failure is safer than using a Summary whose provenance can no longer be established.

A correction enters history before it advances the revision

Return to “Keep only Europe.” The correction first becomes a new raw event. The system does not edit summary_3 in place:

summary_3 covers seq 1..420: Europe and North America
seq 421: user corrects the scope to Europe only

Assembly first decides the correction’s scope. If it applies only to the current response, it can remain in this Turn’s Context view. If it changes the continuing goal, the compression owner rebuilds the covered interval from legal sources and creates summary_4:

summary_4 covers seq 1..420
replaces summary_3
decision_ref: correction at seq 421
current goal: Europe-only market report

The correction itself remains raw in the recent window. Later Turns consume summary_4 only after validation and atomic promotion. The system preserves why the summary changed without making a fresh correction compete with stale compressed text.

The Recent Window must start at a safe boundary

The Recent Window should search backward from its target token size for a complete semantic unit rather than keep a fixed number of messages. Its left boundary must not:

  • split a Tool Call from its Tool Result;
  • split a correction from the active constraint it rejects;
  • cross an unfinished confirmation, Plan item, or execution phase;
  • retain a model claim of completion while dropping later evidence that the action failed.

If no safe boundary fits the budget, Assembly must compress an earlier complete unit, use a larger window, or fail explicitly. Tail truncation must not break execution causality.

Compression acceptance cannot stop at token reduction

A trustworthy Summary must at least verify:

  • preservation of task goals, user constraints, and critical facts;
  • traceability of conclusions to source references that remain valid;
  • dominance of a new correction over the old constraint, rather than coexistence with a stale Summary;
  • preserved Tool Call/Tool Result pairing and causal order;
  • bounded omission and semantic drift across repeated incremental compression.

The later Context Assembly Evaluation and production-evaluation-loop articles operationalize these dimensions. Token reduction is only a cost result. Compression fails when it loses constraints, sources, or corrections, however short the output becomes.

Back to the problem

When an old Summary says “Europe and North America” and a new message says “Europe only,” the model should not guess which sentence wins, and the system should not overwrite text silently:

  1. raw history preserves both the old fact and the correction;
  2. Summary coverage identifies the stable interval represented;
  3. dependency closure links sources, previous Summaries, and Assembly Decisions;
  4. corrections, deletion, authorization, and policy changes invalidate the old revision;
  5. the compression owner rebuilds from legal sources and promotes the result with CAS;
  6. the Recent Window starts at a boundary that does not split Tools, corrections, or unfinished execution.

Compression saves model input, not fact responsibility. A Summary may be replaced, invalidated, and rebuilt. Raw history remains capable of explaining where the current Context came from and why this is the active revision.
